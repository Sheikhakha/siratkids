Quran Reader — UI Fix Preview (Surah Al-Baqarah 2:2 & 2:3)

Layout / interaction only. Segment data, timing & highlight logic, reciter loading, and translation / tafsir content are untouched.

Data findings before building: 1) Tafsir — we only carry one source: Tafsir Ibn Kathir (English abridged · quran.com via live per-verse fetch, cached; Tamil · tamililquran.com from local files). Per your rule “only show tabs for sources we actually have”, the modal shows no source tabs; the Tamil/English language selector remains. All surah-2 verses are present (missing: []). 2) Footnotes — the data is already per-marker: [[ … ]] sits inline inside the translation string at the exact annotated phrase, so inline superscripts are real, not placeholders. Note 2:2 carries no footnotes in the data (its “Al-Muttaqûn […]” parenthetical is single-bracket translation text); 2:3 has 3 markers. 3) There is no existing copy/share/edit icon row in the reader — the only per-verse actions today are the Tafsir text link + footnote ref buttons. The book-icon button is therefore placed in that same action row.

FIX 1 · Word-by-word layout

Today each word+gloss pair is a max-width (not min-width) item in one continuous RTL wrap row. Proposed: each pair is its own flex item with a fixed min-width and generous gaps; RTL order is preserved (rightmost = first word); pairs wrap as whole units (word + gloss never split); Arabic text is clearly larger than the gloss; the verse number stays in the head row (no in-row badge).

FIX 2 · Tafsir as a popup, not inline

Today “Tafsir” expands a panel inline below the verse. Proposed: a dimmed centered modal whose header has surah name + verse number, a verse-jump dropdown, prev/next arrows, a pin (keep-open) toggle and a close X; below it a language selector and an “Aa” text-size control. No source tabs (single Ibn Kathir source). The trigger becomes a book-icon button in the verse action row. Closing returns to reading view — scroll and any playing audio are unaffected. Preview loads the local surah-2 tafsir files; on the live site English is fetched per-verse from quran.ai and cached (same Ibn Kathir source).

FIX 3 · Footnotes as inline popups, not an aggregated list

Today footnotes are stripped out of the translation text and re-listed as numbered buttons that open one popup containing all notes for the verse. Proposed: superscript numbers inline inside the translation text, directly after the annotated phrase; each opens a small tooltip near the marker showing only that footnote; the aggregated list is removed. 2:2 has no footnotes in the data; 2:3 has three inline markers.
